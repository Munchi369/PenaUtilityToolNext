# 起用画面での育成・支配下契約の切り替え：調査と実装計画

2026-10-04作成。以下は当初の調査と実装計画を残したもの。ユーザーの実装指示に基づき実装し、現在の仕様は[起用エディタconcept](../../knowledge/project/lineup-editor.md)、採用判断は[ADR 0013](../adr/0013-edit-player-contracts-in-lineup.md)へ反映した。

操作方式はその後のユーザー指示でボタンからドラッグ＆ドロップへ変更した。最新の判断は[ADR 0014](../adr/0014-drag-player-contracts-between-groups.md)を参照する。モック画像は作成しない。

ユーザーの依頼は、起用画面から育成選手を支配下登録して1軍へ昇格できるようにし、支配下選手を育成契約へ切り替える操作も追加すること。支配下登録の期間制限は本体に合わせる方針をユーザーが選択済み。

### 実DBでの確認

主基準`test-data/reference/year-05/penanto3-year05-end`を、`build/test-db/contract-investigation-<UUID>/penanto3`へコピーして読み取り専用で確認した。原本は接続・更新していない。調査用コードは`build/research/InspectContractData.java`に置いた。

- `SAVE`は自チーム6、`SYSDAY = 309`、`SYSNENME = 5`。支配下登録できる境界日の実例になっている。
- 自チームは支配下69人・育成4人（投手1人、野手3人）。育成4人は全員2軍で、表示背番号は105・108・111・114。
- 現役選手の`SENSYU_NUM`重複はなかった。
- `SENSYU_DATA.SENSYU_NUM`はINTEGER、主キーは`SENSYU_ID`。DB自身に背番号の一意性を任せず、保存側で重複を検査する必要がある。
- `YASYU_SEISEKI`・`TOUSYU_SEISEKI`の主キーは`NUM, NENME, ITINIGUN`。同一年目に1軍・2軍の行が存在する。成績の同期は両方の行を対象にする。
- 育成投手にも打撃成績の行が存在した。投手の契約変更でも打撃成績の背番号同期が必要。
- 能力履歴`SENSYU_NORYOKU`の主キーは`SENSYU_ID, NENME`。契約変更による履歴の作り直しは不要。

## 提案する操作と規則

### 画面

1. 野手・投手の両タブで、中央列に既存の「1軍控え／ベンチ」「2軍」に加えて「育成」を表示する。育成は契約区分による別グループとし、2軍の支配下選手と区別する。
2. 育成の行も選択でき、右の選手パネルで能力・守備適性・起用適性を閲覧・編集できる。
3. 従来の右パネルの守備適性の下（投手は既存の状態欄の下）に「契約」セクションを置く。契約区分と、育成なら「支配下登録」、支配下なら「育成契約に変更」を表示する。背番号は変更先の空き番号を小さい順に調べ、最小の空き番号を自動設定する。操作前に変更後の背番号を表示し、番号選択ダイアログと「空いている最小の番号を設定」の説明文は設けない。ユーザーのモック修正指示によりこの操作方式を採用する。
4. 育成→支配下ではまず支配下の2軍へ移す。そのあと同じ画面で通常の昇格操作・ドラッグにより1軍へ上げられる。契約変更と昇格をまとめて画面全体の「保存」で確定できる。
5. 支配下→育成は2軍選手を対象とする。1軍選手は先に起用から外して2軍へ下げる。DHあり・なしのいずれかのスタメン、または投手の役割に残る選手は契約変更できない。
6. 未保存の契約変更はバッジ・変更件数・変更後の背番号へ即時反映する。「元に戻す」は表示タブの契約変更も取り消す。「再読み込み」は全未保存変更を取り消す。
7. 状態行に「支配下 n/70・育成 n/99」を追加する。期間外・人数上限・空き番号なし・起用中などの理由は操作箇所に短く表示する。

### 契約と昇降格

| 操作 | 提案する条件・結果 |
|---|---|
| 育成→支配下 | 本体の登録可能期間内。変更後の支配下人数が70人以内で、支配下の空き背番号がある。軍は2軍のまま |
| 支配下→育成 | 2軍で、両モードのスタメン・投手の役割にいない。変更後の育成人数が99人以内で、育成の空き背番号がある |
| 育成の1軍登録 | 契約が育成のままでは禁止。ドラッグ・自動並び替えが契約を暗黙に変えることも禁止 |
| 支配下へ変更後の1軍登録 | 編集中の新しい契約区分で判定する。既存の1軍29人・外国人枠・再昇格待ち・自動降格の規則を適用 |
| 契約変更と再昇格待ち | `TOROKU`を消さない。契約変更だけでは待機日数を新設しない。読み込み時1軍だった選手を最終的に2軍（育成を含む）として保存する場合は、既存の10日制限を適用 |
| 背番号 | 支配下の候補は0〜99、育成への新規割当候補は本体の自動割当と同じ101〜199。現役選手の使用番号と編集中の割当を除外し、最小の空き番号を自動設定する。支配下・育成の番号空間は別々に扱う。操作を取り消した選手の割当は解放し、取消・他選手の変更に応じて操作前の番号表示を更新する |
| 選手の同一性 | `SENSYU_ID`・所属球団を維持し、契約区分と背番号を一体の変更値として扱う。引退・解雇・再入団による代用はしない |

支配下→育成には本体の直接対応する期間規則が見つからない。初期案では逆方向も支配下登録と同じ期間に揃える。これは本体で確認した事実ではなく、期間外で契約を往復させる操作を避けるためのNext側の提案である。

年俸、契約金、FA関連値、入団・ドラフト・能力・タイトル履歴は契約区分の変更によって書き換えない。

## 保存設計

- 読むテーブル：既存の`SAVE`・`SENSYU_DATA`・`KIYO`に、同期対象を確認する`YASYU_SEISEKI`・`TOUSYU_SEISEKI`を追加する。
- 変更するテーブル：既存の`KIYO`・`SENSYU_DATA`に、今の年目の`YASYU_SEISEKI.SEBANGOU`・`TOUSYU_SEISEKI.SEBANGOU`を追加する。成績行は存在するものを更新し、欠けている行をこの機能で新設しない。
- `SENSYU_DATA`の追加更新列は`SENSYU_NUM`。対象は国内現役の自チーム選手なので`GENINFLG = 1`を維持する。
- `SENSYU_NORYOKU`・過去年目の成績・履歴・`IKUSEI_SHIMEI`は更新しない。番号は既存の使用状況から選ぶため、本体のドラフト用番号採番カウンターを流用する必要はない。
- `SAVE`の自チーム・日付・年度、全自チーム現役選手の集合・契約番号・年目・既存の編集列、同期対象の成績行キーと背番号を読み込み時に保持する。加入・離脱・他ツールの背番号変更・日付進行・成績行の追加削除も競合として検出する。
- 操作時と保存時に同じ規則で検査する。DBへ書く入口でも検査を行い、UIを経由しない呼び出しで期間・人数・育成の起用制限を迂回できないようにする。
- 既存の保存前比較→バックアップ→トランザクション内再比較→一括更新を拡張する。契約番号・今季成績の背番号・起用・軍の更新を1トランザクションにまとめ、途中失敗はすべてrollbackする。
- 保存後は起用と現役選手一覧を読み直し、選択中のタブ・DHモード・選手IDを維持する。選手ID基準のピンも維持する。

## 実装の順序

1. **仕様の確定と文書更新**：起用conceptに育成表示、契約変更、期間、番号・枠・待機規則、成績同期の読み書き範囲を追記する。紹介文が変わるためproject indexも更新する。育成への変更はNext固有の判断として新しいADRに残す。
2. **読み込みと編集モデル**：育成を含む選手抽出、契約区分と番号の変更値、選手年目、SAVEの比較情報、成績背番号のスナップショットを追加する。既存の`PlayerRegistration`を共通で使えるか検討し、不要な二重定義を避ける。
3. **ドメイン操作**：支配下登録・育成への切り替え、番号割当・契約枠検査、取消と変更件数を実装する。昇格・コピー・ベンチ生成・自動並び替えの全入口を、編集中の契約区分で制限する。タブ単位の取消が他タブの契約変更と合わさって枠超過・番号重複になる場合も検査する。
4. **保存**：競合比較とWriterを拡張し、番号・成績・軍・起用を既存のバックアップとトランザクションで保存する。書き込み先にゲームDBのDDLは追加しない。
5. **UI**：育成グループ、右パネル下部の契約操作、自動設定される背番号の表示、無効理由、枠人数、未保存表示を追加し、野手・投手の両タブを描画確認する。
6. **回帰確認**：契約保存後の起用・現役一覧・選手詳細、本体での支配下/育成表示と起用可否を確認する。コミット・PUSHは別途依頼があるまで行わない。

## 検証計画と完了条件

- 単体テスト：期間境界212/213/308/309、支配下69→70と70→71拒否、育成98→99と99→100拒否、最小の空き背番号の自動割当、複数選手の連続変更で重複しないこと、重複・番号枯渇、変更→取消による番号解放、タブ単位取消時の他タブとの整合。
- 起用操作：育成の直接1軍登録と自動選出を拒否、支配下変更後は通常の昇格を許可、1軍・スタメン・役割に残る選手の育成変更を拒否、両DHモードを検査する。
- 待機：既存`TOROKU > 0`の契約往復でも昇格不可、1軍から育成として保存した場合の10日設定、86/87/279日目の既存例外、保存前に操作を取り消す場合。
- Derbyテスト：テストごとのReference DBコピーで、投手・野手それぞれの契約変更を保存して再取得する。投手の打撃・投手成績と1軍・2軍行の背番号が同期し、過去年目・選手ID・年俸・履歴が維持されることを確認する。
- 競合・失敗：外部の番号変更、新しい選手の加入、日付/年目進行、成績行追加削除、バックアップ失敗、成績同期途中の失敗を検査し、部分的な保存が残らないことを確認する。
- 描画：育成の選択、守備適性の下にある契約操作、自動設定予定の背番号、期間外・満員時の無効表示、契約変更後のグループ移動・新背番号、保存後の選択維持を確認する。
- `./gradlew.bat test --tests "io.github.munchi369.penautilitytoolnext.knowledge.OkfBundleConformanceTest"`と`./gradlew.bat check`を順番に実行する。配布物を作る際は`./gradlew.bat build`も実行する。
- 本体の動作確認は一時コピーを使い、支配下登録した選手が通常の一軍入替で昇格でき、育成変更した選手が育成一覧に移って1軍起用から除外されることを確認する。

実装後は単体テスト、Reference DBの一時コピーでの契約保存・成績同期・競合・rollbackの検査、野手・投手の画面描画と契約変更のドラッグ操作を実施した。ゲーム本体を起動しての切り替え動作は未確認。コミット・PUSHは行っていない。
